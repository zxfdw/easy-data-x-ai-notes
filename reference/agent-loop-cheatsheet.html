Agent 循环

一页看完：循环怎么转、每圈消息怎么变、什么时候停。

一句话

把"模型要求调工具"和"工具返回结果"交替追加进同一份消息列表，直到模型输出里不再有 tool_calls。

状态机

        ┌─────────────────────────────────────────┐
        │  发 messages 给模型                      │
        └────────────────┬────────────────────────┘
                         ↓
              ┌──────────────────────┐
              │ 输出里有 tool_calls？ │
              └───────┬──────┬───────┘
                   有 │      │ 没有
                      ↓      ↓
        ┌──────────────────┐  ┌──────────────────┐
        │ 执行工具          │  │ 这是最终回答      │
        │ 把结果追加到      │  │ 循环结束          │
        │ messages          │  └──────────────────┘
        └────────┬─────────┘
                 └──────→ 回到开头

保险丝max_rounds 只是防跑飞的次数上限，不是循环条件。

每圈消息列表的变化

圈消息列表内容
1[system, user]
2[system, user, assistant(tool_calls), tool(result)]
3上面 + [assistant(tool_calls), tool(result)]
n…持续追加，直到 assistant 不再带 tool_calls

模型没有"记忆"：它每圈看到的都是重新发过去的完整历史。

三个角色

assistant（带 tool_calls）
模型要求调用某个工具，附带参数（JSON）。这一步不产生答案，只产生意图。
tool / function（结果）
程序真正执行工具后，把返回值作为一条消息贴回去。模型只能通过这条消息"看到"外部世界。
assistant（不带 tool_calls）
模型的最终回答。循环的出口。

常见坑

  • 忘了回传结果：模型会一直重复调同一个工具，因为它永远看不到反馈。
  • 回传格式不对：工具结果必须带对应的 tool_call_id，否则模型会认为"这结果不是我要的"。
  • 没设上限：模型陷入反复查询时会烧掉大量 token。
  • 把 max_rounds 当循环条件：写成"必须转满 N 圈"，逻辑就反了。
