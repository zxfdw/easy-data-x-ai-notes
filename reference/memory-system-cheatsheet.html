Agent 记忆系统

一页纸：D4 八个脚本各管什么、记忆管理的四条工程红线、以及 I7 划出的工业接口边界。

D4 八个脚本速查

脚本主题一句话结论
d4_1ReAct 推理循环Agent 自主决定调哪个工具、调几次；max_steps 是安全阀
d4_2无记忆基线每轮独立，重启即失忆，用户要反复自我介绍
d4_3有记忆版本记住身份与偏好，推荐落到个性化口径
d4_4完整记忆 Agent记忆跨进程持久化，交互式命令行
d4_5多用户隔离user_id 命名空间；过滤在查询构建阶段
d4_6记忆压缩多条变一条换压缩比；画像 + 事实库分层
d4_7冷热分层冷数据必须移出热索引，不能只靠排序沉底
d4_8记忆清理KEEP → ARCHIVE → DELETE；硬删级联主库/向量/缓存

记忆管理四条工程红线

  1. 隔离在查询里做，不在结果里做。 检索后再丢 = 先把别人的数据取出来再扔掉，既浪费又危险。
  2. 压缩是"多条变一条"，不是把字压扁。 画像承载稳定约束，事实库承载长尾细节。
  3. 冷数据要真的移出热索引。 只靠排序沉降，热索引的负担一点没减。
  4. 删除要分级，且级联。 KEEP / ARCHIVE / DELETE 三档；硬删必须同时清主库、向量、缓存。

一句话：存进去是一行代码的事；隔离、压缩、分层、清理，才是要设计的地方。这也正是 P3 那句"难的不是记住，是忘掉"的工程版本。

I7 划出的工业接口边界

维度内容
数据关系Source / Memory / PreparedContext / Handoff 四者的串联
可追溯不可变修订、证据引用、生命周期管理
接口边界Server / Client / Core SDK / HTTP / MCP 各管一段
检索契约全文、向量、混合检索各自的约定

D4 讲"从零搭一遍、看懂原理"，I7 讲"工业实现怎么把这些拆成可替换的接口"。一个讲原理，一个讲边界。
