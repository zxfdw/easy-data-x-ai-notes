Easy Data × AI · 第 2 课（对应 Task 2 · D1）

Agent 循环：模型每一圈看到了什么

跑完 d1_4 之后，你能说清一件事：模型每一圈看到的输入到底是什么，以及谁决定继续下一圈。

  • 预计耗时 8 分钟
  • 关联 d1_4 / d1_6
  • 类型 概念 + 观察

先看你已经跑出来的现象

你跑 d1_4 时，真实输出是这样的（来自你自己的终端记录）：

>>> 模型决定调用工具：query_knowledge_base
>>> 工具参数：{'query': 'SeekDB 支持的检索方式 混合检索实现原理'}

>>> 知识库检索结果：
seekdb 支持关键词、语义向量和混合检索。
...

>>> 模型决定调用工具：query_knowledge_base      ← 又调了一次
>>> 工具参数：{'query': 'SeekDB 混合检索实现原理'}

>>> 模型决定调用工具：query_knowledge_base      ← 第三次
>>> 工具参数：{'query': 'SeekDB 混合检索 具体实现 BM25 向量 融合'}

>>> 模型最终回答：...目前的知识库记录中未包含底层的打分算法...

请你先停一秒：这里调了三次工具，是谁要求的？

不是程序写的循环次数，也不是你指定的。是模型自己：它前两次拿到结果后，觉得还不够，于是换了个更具体的查询词再问一次。

这就是 Agent 与"一次调用"的分界线

普通调用里，程序决定"要不要再问模型"。
Agent 里，模型自己决定要不要再调工具，程序只负责执行和回传。

循环的解剖：每一圈多了一段消息

关键在于：每一圈，程序都会把新结果追加进消息列表，然后整份重发。模型并没有"记住"什么，它每次看到的都是完整的对话历史。

圈次模型收到的输入（messages）模型的输出
第 1 圈 system + user 问题 tool_calls：查"检索方式 实现原理"
第 2 圈 上面全部 + 第 1 次工具结果 tool_calls：换词再查一次
第 3 圈 上面全部 + 第 2 次工具结果 tool_calls：第三次查（更具体）
第 4 圈 上面全部 + 第 3 次工具结果 不再调工具，直接给出最终回答

所以"循环"的本质只有一句话：

退出条件

模型输出里还有 tool_calls → 执行工具，追加结果，再转一圈。
模型输出里没有 tool_calls → 那就是最终回答，循环结束。

这正是 d1_6 里你看到的 [行动] → [观察] → 回答：[行动] 是模型要调工具，[观察] 是程序把结果贴回去。d1_6 比 d1_4 多出来的，只是换了更聪明的循环实现（框架托管），骨架完全一样。

那 max_rounds=5 是干嘛的？

它是保险丝，不是循环条件。d1_4 里写了 max_rounds=5，意思是"最多转 5 圈，防止模型陷入无限查下去"。

正常情况下，模型第 4 圈就自己收尾了，你不会看到它把 5 圈用完。

连回你的公式

你 Task 1 写的「Agent 能力 = 模型能力 × 数据质量 + 流程编排」。
这个循环就是流程编排最核心的那部分：不是写多复杂的代码，而是把工具结果正确地喂回去、让模型有下一圈可转。
