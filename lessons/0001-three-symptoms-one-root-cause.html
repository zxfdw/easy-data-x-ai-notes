三个毛病，一个根因

读完 F1/F2 之后，你能把"AI 不好用"的三种典型表现，归结到同一个原因上，并说清每种表现该补哪一种数据。

  • 预计耗时 10 分钟
  • 关联 F1 / F2
  • 类型 概念 + 判断

先接住你自己那句话

你在 Task 1 打卡里写过一句话，我印象很深：

「它们的核心都是数据，只是数据在 Agent 生命周期的不同环节被不同方式使用。」
并且给出了公式：Agent 能力 = 模型能力 × 数据质量 + 流程编排。

这一课做一件事：给这个直觉装上证据。让你不只是"感觉是这样"，而是能从具体症状反推到具体数据缺口。

三个毛病

F1 把大模型最常见的三种"不靠谱"拆开了：

表现你会怎么说它
幻觉"听起来挺像那么回事，一查根本不是"
知识截止"它说的都是老黄历了"
个性化盲区"答得没错，但跟我的情况没关系"

多数人的第一反应是：换个更强的模型。

F1 给的结论正相反，而且三条指向同一个根因。

同一个根因

F1 的核心判断

大模型只有训练数据，没有你的数据。

拆开看是这样对应的：

毛病缺的是哪种数据该补什么
幻觉可验证的事实数据给它一个能检索的知识库
知识截止实时数据接入会持续更新的数据源
个性化盲区用户 / 业务数据建一个记忆系统

所以正确的动作不是"换脑子"，而是补数据。

连回你的公式

你那句「不是换更强的模型，而是把数据管好」：F1 用一张表把它证明了一遍。
你当时的直觉是对的，现在有了可执行的对应关系。

那 F2 补上了另一半

F1 说"缺数据"，F2 回答"数据从哪来、以什么形式进来"。它把 Agent 的经典架构拆成四块，并指出一个关键点：Agent 不是一问一答，而是一个循环。

传统对话：用户输入 → 模型生成 → 返回结果        （单次）

Agent：  推理 → 行动 → 观察 → 继续推理 …        （循环）

更有意思的是 F2 最后那张对照表，把四个让人眼花缭乱的词全部拉回数据：

能力表面概念数据本质
RAG检索外部知识知识数据的检索
MCP标准化工具接入数据接入的标准化
Skill调用结构化技能经验数据的结构化
Memory记住与学习数据的积累与召回

这与你在 Task 1 写的判断几乎逐条对上：内核都是数据，只是位置和用法不同。

记住这一句就够

模型决定了 Agent 能"想多好"，数据决定了 Agent 能"做多好"。
