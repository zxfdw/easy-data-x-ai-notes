Easy Data × AI · 第 5 课（对应 Task 5 · P3 + I4）

记什么容易，忘什么才难

学完这一课，你能分清 Agent 的三类记忆，并理解为什么「忘」比「记」更考验设计——以及文件怎么才能被 SQL 直接当成临时表来查。

  • 预计耗时 13 分钟
  • 关联 P3 记忆框架 / I4 File SQL
  • 类型 概念 + 安全 + 动手

先接上一课的话头

第 5 课解决的是"这次要不要查"。但查之前还有一个更前面的问题：Agent 凭什么"认识你"？

它的上下文窗口是一张桌台，每次新对话就被清空。P3 的原话很扎心：这不是体验瑕疵，是 AI 从"工具"变"助手"的根本障碍。

三类记忆，缺哪类就用不上

类型存什么类比缺了会怎样
语义记忆事实和知识百科全书每次都要重新自我介绍
情景记忆过去的经历日记本同一个坑让你掉两次
程序记忆行为规则操作手册不知道该怎么跟你打交道

P3 给了个很实用的分析工具：觉得 Agent"不够懂我"时，先问它缺的是哪种记忆——不记得事实？不记得经验？还是不懂规矩？三种缺失对应三种完全不同的修法。

另外记住一点：程序记忆是三类里唯一 Agent 能自我修改的——这就是"从反馈中学习"的底层机制（下次讲 Skill 时会接上）。

为什么说"忘"比"记"难

这次我实测体会最深的是这一点。往 PowerContext 里写 6 条记忆非常顺——一次全进，没有任何阻力。

但检索"回答风格偏好"时，它把这两条都捞了回来：

查询「回答风格偏好」→ 命中 2 条 (mode=hybrid)
    · score=0.033  张博偏好简洁的回答，不喜欢过度铺垫和客套   ← 语义记忆（要什么）
    · score=0.032  回答代码类问题时，先给解释再给示例          ← 程序记忆（怎么答）

两条分数几乎一样。可在语义上它们是两个类别：一条说"用户要什么风格"，一条说"我该怎么回答"。如果 Agent 拿着后者当前者执行，就会把一条行为规则误当成用户偏好。

记忆的难处不在存不进去，在记多了之后分不清该想起哪条。

这也是 P3 用"永远记不住你的同事"开场的用意——真正要设计的，是什么该留、什么该降权、什么该过期。

File SQL：文件为什么能当表查

I4 换个战场：Agent 常遇到只查一次的文件（用户传的 CSV、导出的日志）。传统链路是建表 → 导入 → 查询 → 清理，每一步都是失败点。

File SQL 把它压成一条语句——文件成了语句级临时关系：

SELECT customer_id, SUM(amount)
FROM read_csv('/workspace/orders.csv')
GROUP BY customer_id;
-- 没有 CREATE TABLE，也没有 LOAD DATA，查完不留持久表

我按课程五步闭环自建了实现：

步骤动作我的真实结果
1 发现glob 枚举候选文件✅ 找到 orders.csv
2 描述执行前定列名与类型✅ amount 识别为 DOUBLE
3 查询GROUP BY + HAVING✅ C01 1018.0 / C04 1500.0
4 关联跨文件 LEFT JOIN✅ 5 条带客户等级
5 导出COPY TO 原子发布✅ export.csv

先想一想为什么 Schema 必须在 SQL 执行前就确定？

因为客户端要接收第一行结果前，就必须知道结果有哪些列。所以文件扫描得先接入 SQL 的编译期与执行计划——这也是 I4 反复强调"Reader 只产出数据批次，关系运算交给 SQL 引擎"的原因。

只读 ≠ 安全

I4 用一整节讲 Path Guard。我自己实现时才发现这条检查链一点都不多余——不做路径校验，/etc/passwd 这类路径能直接被读进去：

【安全边界】Path Guard 拦截越界路径
  ✅ 已拒绝：路径越界，拒绝：/etc/passwd（不在受控根目录）

任意文件读取本身，就足以泄露密钥、配置和系统信息。所以 File SQL 必须默认关闭、限定唯一根目录（secure_file_priv）、做 realpath + 目录边界 + 普通文件三重检查。这条对我手上的研发知识库直接相关。

接到你的实际场景

  1. 研发知识库的"三类记忆"。 事实（标准号、材料牌号、注册证号）走语义；经验（某次试验为什么失败）走情景；规则（评审流程、变更留痕要求）走程序——三类分开存，检索才不会串。
  2. 周报/试验数据的一次性分析。 团队导出的 CSV、检测报告表格，用 File SQL 直接查掉，不用为"看一次"建表导库。
  3. "先小样本再全量"。 I4 给 Agent 的准则：先 glob 发现、再 DESCRIBE 看列、再 LIMIT 预览、最后才全量——这条直接可以写进你自己 Agent 的工具协议。
