Easy Data × AI · 第 7 课（对应 Task 7 · P4 + I6）

Skill 不是更长的提示词

学完这一课，你能把 Skill 从"我写的一段指令"，看成"一份要被存储、索引、检索的数据"——并知道它什么时候该从文档升级成 MCP 工具。

  • 预计耗时 12 分钟
  • 关联 X2 / X5 / PowerContext
  • 类型 概念 + 实测 + 工程

先接上一课的话头

第 5 课讲记忆时留了个伏笔：程序记忆是三种长期记忆里唯一一种 Agent 能自我修改的——"回答太长了"多说几次，Agent 给自己加一条"回答要简洁"的规则。

P4 换了个角度：这套"该怎么做"的规则，能不能不只存在 Agent 脑子里，而是写成一份文档，放到书架上？

Skill = 被外部化、结构化了的程序记忆。程序记忆是 Agent"内化"的行为规则，Skill 是把它"外化"成可以管理、共享、检索的文档资产。

这句话为什么重要？因为一旦经验变成了文档，它就不再是某个人或某个 Agent 专属的，而是变成了可被管理的数据。而只要涉及数据管理，前面几课讲过的那套（存储、索引、检索、更新）就全都回来了。

省 76% 上下文，靠的不是"提示词技巧"

X2 这个示例做的事很朴素：把一份 SKILL.md 解析进 seekdb，然后对比两种加载方式。

方式上下文字符估算 Token
全量注入（把 Skill 一股脑塞进提示词）1,721~573
按需加载（seekdb 混合检索）405~135

同样的内容，按需取只要 ~135 token，省掉约 76%。而且取回来的不是整篇，是“描述 + 最相关的 5 条规则”。

"要不要全量加载"从来不是提示词技巧，是检索问题。

这和第 3 课讲的混合搜索是同一套机制，区别只是检索对象从“知识文档”换成了“技能文档”。

碎片化：知识库分散的老毛病，换了身衣服

P4 把 Skill 碎片化拆成三层，每一层都很眼熟：

层面表现
项目隔离项目 A 攒的规则，开新项目 B 要手动搬
工具隔离Cursor 的 .mdc、Claude Code 的 CLAUDE.md、ChatGPT 的自定义指令，格式互不兼容
人员隔离同事的好规则只能靠发消息 + 手动粘贴，半年后各自分叉

把它和第 2 课对照一下就明白了：知识库分散 → RAG 检索不到 → AI 答不好；Skill 分散 → Agent 找不到最佳技能 → 行为不专业。同一类问题，同一个根因：经验数据没有被结构化地管理。

换个视角，解法就清楚了：别把它当工程问题（写同步脚本、格式转换器，永远在追赶新格式），把它当数据管理问题：像管理知识库一样管理技能库。

从 Skill 到 MCP：解决"怎么被调用"

Skill 解决的是"这件事该怎么做"，但不解决"怎么被不同客户端统一发现、统一调用"。X5 那个 50 行的 MCP Server 就是补这一层：

  1. 稳定名字：review_code_diff，不是 helper
  2. 清晰描述：告诉 Agent 什么时候该用它
  3. 结构化参数：diff、focus
  4. 可验证返回：按严重程度分级的审查结果

实测端到端跑通：起 stdio server → list_tools 发现工具 → call_tool 调用，返回结构化审查报告。

P4 的判断是：Skill 还在快速迭代时，写成文档最灵活；等它稳定了、要跨工具复用了，就考虑 MCP 化。文档 → 工具的升级点，是"稳定"和"要被多方调用"。

上下文工程的边界，是 I6 想划的那条线

I6（上下文工程概述）目前在课程里还标着“开发中”，但它列出的方向已经把话说清楚了：要理清 Source、Memory、PreparedContext、Handoff 各自的职责边界，再谈项目范围、相关性、上下文预算。

一句话：上下文工程 ≠ 把更多内容塞进提示词。

这跟 X2 的对比实验正好互证：上下文是有限资源，关键不是“塞得多”，是“取得准”。第 1 课那句公式又出现了：Agent 能力 = 模型能力 × 数据质量 + 流程编排，这次落在“数据质量”上。

一个顺手的教训：跑不通，先看环境

这次两个坑都不是代码写错，是依赖版本没对齐。

先自己猜PowerContext 报 TypeError: Expected an instance of httpx.AsyncClient but got httpx2.AsyncClient，你会先改代码，还是先查依赖？

查下来是硬冲突：langchain-openai（第 6 课 RAGAS 拉的）要求 openai<3，而 PowerContext 依赖的 pydantic-ai-slim 2.47 要求 openai>=3.8——同一环境无解。把 PowerContext 单独放进隔离环境就好了。

另一个：X5 用 mcp 1.x 的 FastMCP 导入路径，而本地装的是 mcp 2.x（已改名）。课程 requirements.txt 其实写了 mcp[cli]>=1.28.1,<2，是本地环境没按它锁定。先看报错是不是环境（版本、权限、模型名）问题，再去动代码，这条在第 6 课也吃过一次。

接到你的实际场景

把这一课接到自己的 AI 工作流上：

  1. 把散落的规则收拢成“技能库”。 Cursor Rules、CLAUDE.md、各种 Prompt 模板，先盘点有多少份、存在哪、谁维护，这本身就是 P4 的课后行动题。
  2. 规则多到塞不下时，别硬塞。 用检索按需加载，而不是把所有 Skill 都堆进提示词。
  3. 稳定的流程再 MCP 化。 还在天天改的先做成 Skill 文档；跑顺了、要让别的工具也能调用，再包成工具。
  4. 报错先分环境还是代码。 版本冲突、权限、模型名这三类，占了"跑不通"的一大半。
