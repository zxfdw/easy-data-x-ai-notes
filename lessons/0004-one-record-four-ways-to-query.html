Easy Data × AI · 第 4 课（对应 Task 4 · D2 + I3）

同一份数据，四种查法

学完这一课，你能回答一个问题：为什么"把数据存进向量库"只是第一步，一条记录要能被四种方式同时查到才算真的可用。

  • 预计耗时 12 分钟
  • 关联 d2_3 / d2_4 / d2_5
  • 类型 概念 + 归因 + 动手

先回答上一课留下的悬念

第 3 课你说过一句话：混合搜索是把向量和全文合起来用。但那还是"两个检索引擎"的视角。

D2 把镜头往后拉了一格，问的是更前面的问题：这份数据本身，长什么样，才能被这几种方式查到？

I1 里那句"模型负责想，数据库负责记住"，到 D2 才真正落地——不是随便找个数据库塞进去，而是同一条记录，要同时具备四种可查性。

四种查法，缺一个都会出事

查法靠什么实现缺了它会怎样
精确编号
E-4012、型号、版本号		全文 / 标量索引用户报错码来查，检索"漂"到同主题的其他文档
语义
"怎么设计权限"		向量索引用户不照抄原文就查不到，只能靠猜关键词
关键词
专有名词原样命中		全文索引（BM25）术语、编号这类"必须找准"的查询失去保障
属性过滤
版本 / 分类 / 权限		标量字段结果范围失控，越权数据可能流经系统

关键认知：这四个不是"四选一的检索策略"，而是同一条数据的四种"面孔"。存的时候就要把这四种信息都带上，而不是查的时候现想办法。

你在 d2_4 亲手看到过"跑偏"

d2_4 拿同一组查询，分别走纯向量和混合搜索。回看你的真实输出：

查询：「怎么设计用户权限」

  纯向量搜索                          混合搜索（向量 + 全文）
  [1] 连接池配置：最大连接数建议 ...    [1] 访问控制架构设计：基于 RBAC ...

查询：「数据库性能优化」

  纯向量搜索                          混合搜索（向量 + 全文）
  [1] 连接池配置：最大连接数建议 ...    [1] 数据库查询性能优化指南 ...

两问都跑偏到"连接池配置"。原因不神秘：查询里带"数据库"这个大词，向量空间里"数据库"是个强语义簇，于是同主题但不对题的文档被一起捞了上来。

而全文那一路是"字面重合"，"权限"没出现在连接池文档里，自然不会被顶到第一。

所以要修正一个直觉：混合搜索补的不是"精度"，是"另一条判断路径"。

向量靠语义相近，全文靠字面重合——两套分数体系不同（这正是 RRF 比名次而不是比分数），互为兜底。单靠一路，撞到它的盲区就整条跑偏。

三个数字，看懂"切"和"查"是两件事

d2_5 用三种分块策略跑同一批数据，结果是这样的：

策略块数均长Recall@3它胜在哪
固定 overlap5186 字60%实现简单，但在章节边界处切断语义
动态 overlap6185 字100%在标题 / 段落边界加大重叠，低成本改善边界召回
父子 chunk9104 字60%子块精准检索 + 父块完整上下文，适合多跳

别急着记"动态 overlap 最好"。这一课真正要带走的是一句话：

分块策略 与 检索后端 是两个独立变量。

"怎么切"决定上下文完整性；"用什么查"决定召回方式。混着调，你永远不知道是哪个在起作用。这也是 d2_5 脚本开头那句提示的意思。

顺带一个诚实的边界：这次语义分块没跑成——它需要单独的 embedding 服务，我方 Key 无对应模型权限，脚本自动跳过了这一路。所以上面三行不含语义分块，不能当作"语义分块不如动态 overlap"的证据。

一个复现的坑：写入成功 ≠ 立刻可检索

d2_1 写完立刻跑 d2_2，第一条语义查询返回"（无结果）"；隔几秒重跑就正常。

但同一时刻 d2_3 混合搜索却正常出结果。这说明什么呢？

先自己猜如果你是设计者，为什么全文那一路能先用上？

一个合理推测：向量索引是异步构建的（尤其 ANN 结构），而全文索引构建快得多。所以"混合"里先有返回，另一条路追上以后结果才完整。注意这是推测，不是课程结论——但工程上它提醒你一件事：别把"写入成功"当成"可检索"，异步系统里这两件事之间有时间差。

接到你的实际场景

把这一课接到你手上的事——研发知识库、注册资料、周报汇总：

  1. 一条注册资料，要能按什么查？编号（标准号）、语义（"这类材料的生物相容性要求"）、关键词（材料牌号）、属性（版本 / 状态 / 密级）。四种都要有，缺一个就会在某类查询上整条失效。
  2. 当 AI 在知识库里答得不对，先别换模型。按 Task 3 那个三层归因走一遍：是没检索到（数据层）？检索到但答歪（生成层）？还是需求本身模糊（业务层）？
  3. "先过滤、再召回、最后调模型"——I3 的顺序。版本、密级这类过滤要在检索阶段生效，模型只处理过完筛的内容，省的是又慢又贵的调用。

这仍然扣着你在 Task 1 提出的公式：Agent 能力 = 模型能力 × 数据质量 + 流程编排。第 3 课讲的是"流程编排"里怎么合；这一课讲的是"数据质量"里怎么存。
